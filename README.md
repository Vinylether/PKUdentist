# 北京大学 i看牙自动预约

默认预约 **洁治(洗牙)**。使用 Chromium 登录北大门户，通过指定入口进入 i看牙，复用网站会话，在**北京时间每天 09:00**查询**七天后的同一天全天**，按时段从早到晚选择。默认查询 10 分钟（每 5 秒一次），找到号源即停止。

已经实际登录核对预约说明、洗牙项目、医生列表、号源接口和预约记录。当前账号检查时洗牙无号，因此未创建真实预约；提交逻辑依据网站前端实际使用的 `Upload` 接口实现，仍须在真实放号时验证成功结果。预约规则见下文。

## i看牙预约规则

2026-10-15 登录北大门户并进入 i看牙，在“预约说明”及首页核对：

- 每日北京时间 09:00 放出下周同一天的初诊号，提前一周预约。
- 默认项目在系统中的准确名称为“洁治(洗牙)”。
- 仅支持北大学生及教职工本人实名预约；每人每周只能预约一个初诊号。
- 就诊须提前 15 分钟到口腔科四楼分诊台取预约条。
- 取消预约须提前至少 4 小时，否则按爽约处理。
- 爽约一次暂停网络预约一个月；一年累计三次及以上，从第三次起暂停三个月。
- 法定节假日不可预约。页面列出的预约时段：工作日 08:00–11:40、13:30–16:50；周末 08:30–11:30、13:00–16:20。实际号源时间以接口返回为准。
- 医生停诊时，系统会自动取消预约并提醒。

本地首次检查时“洁治(洗牙)”显示无号；这只是检查当时的状态。

入口：https://portal.pku.edu.cn/portal2017/util/portletRedir.do?portletId=dentistAppointment

## 安装

需要 Python 3.9+。在项目目录执行：

```sh
uv sync
uv run playwright install chromium
```

账密和预约参数统一放在 `config.yaml` 中，现有账密已迁移。新安装时复制 `config.example.yaml` 为 `config.yaml`，填写带引号的 `username` 和 `password`。程序不会输出密码；`config.yaml`、会话和预约记录已加入 `.gitignore`。`.private/` 含登录令牌和个人信息，请勿分享或提交版本库。

依赖由 `pyproject.toml` 和 `uv.lock` 管理，`uv sync` 创建并同步 `.venv`。

## 使用

首次登录或会话失效时：

```sh
uv run python dentist.py login
```

需要手机令牌时，在终端输入当前动态码（不回显）。图形桌面下也可执行 `uv run python dentist.py login --headed`，在浏览器中完成验证码或二次验证。无人值守时若需要再次验证，程序会退出，不会绕过验证。

查看当前页面及洗牙状态：

```sh
uv run python dentist.py inspect
```

预约下一次放号：

```sh
uv run python dentist.py run --submit
```

程序等待下一个北京时间 09:00，提前五分钟打开浏览器、检查登录及联系方式，到点查询七天后的全天号源。机器须保持开机联网，终端须持续运行。**本项目交付时未启动预约任务。**

指定放号日，例如 10 月 16 日 9 点抢 10 月 23 日的号：

```sh
uv run python dentist.py run --at 2026-10-16 --submit
```

指定日期的 09:00 已过时，立即查询该放号日对应的下周当天。也可以用 `run --now --submit` 立即查询今天加七天的号源。不会选择其他日期或其他项目。

省略 `--submit` 是预览模式：会查询和显示号源，但绝不调用预约提交接口；仍按相同的时间和次数限制运行。配置文件中的 `max_attempts` 改为 `1` 可只查询一次。

## 配置

`config.yaml`（完整示例见 `config.example.yaml`）：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `username` | 需填写 | 北大账号，使用引号包裹 |
| `password` | 需填写 | 密码，使用引号包裹 |
| `project` | `洁治(洗牙)` | 必须与网站项目名称完全一致 |
| `interval_seconds` | `5` | 无号时的查询间隔，最短 5 秒 |
| `max_attempts` | `120` | 最多查询次数 |
| `login_timeout_seconds` | `180` | 等待登录和二次验证时间 |

时间计算固定使用 `Asia/Shanghai`，不受服务器本地时区影响。

## 结果与重复提交保护

- 提交前检查预约记录：目标周已有未取消的初诊记录时停止。
- 单进程文件锁阻止同时启动多个预约任务。
- 提交前将号源和 `pending` 状态写入 `.private/booking-YYYY-MM-DD.json`；接口成功后改为 `accepted`，记录复核成功改为 `confirmed`。
- 响应超时、断网等情况改为 `unknown` 后停止。明确拒绝则记录 `rejected`。同一日期只要存在状态文件就不会再提交。
- 如果需要重试，先在网站“预约记录”确认没有预约成功，再移走相应状态文件。程序没有自动取消预约的功能。
- 网站返回成功也请以“预约记录”为准。取消须提前至少四小时，详情见预约规则。

退出码：`0` 为命令正常完成（预览找到号源或提交返回成功）；`2` 为无号达到次数上限、验证未完成、已有记录等主动停止；`1` 为浏览器等运行异常；`130` 为手动中断。`accepted` 不代表记录已完成复核，请查看状态文件。

## 检查

```sh
uv run python -m unittest -v
```

测试覆盖北京时间放号、跨年日期、真实时段文本格式、仅选择目标日、按时间排序、每周限号、预览不提交及提交超时后不重试。不以真实预约来测试提交。
